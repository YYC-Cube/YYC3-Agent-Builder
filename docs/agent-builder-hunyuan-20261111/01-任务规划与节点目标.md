## 规划总则

> **执行有规划，规划有节点，节点有目标，目标可评估**

以《00-项目现状审核报告》§4.2 问题分级清单为唯一输入，按 P0 → P1 → P2 → P3 顺序逐项闭环；每项均须「代码修复 + 回归测试 + 文档同步」三件套完成方可标记 ✅。

## 一、总体目标

清零 P0/P1 必修缺陷，补齐执行引擎测试覆盖与运行时可观测性，建立可跨会话衔接的文档机制，使项目达到「可预发布评审」状态。

## 二、阶段划分

| 阶段 | 名称 | 目标 | 交付物 | 状态 |
| --- | --- | --- | --- | --- |
| Phase 1 | 文档与日志机制 | 调研报告落盘、会话四件套、结构化日志 | docs 会话目录 + `lib/logger.ts` + 机制规范 + CHANGELOG | ✅ |
| Phase 2 | P0 致命缺陷清零 | 条件分支 / JS return / 无鉴权 | `safe-executor.ts`、`api-guard.ts`、`route.ts` | ✅ |
| Phase 3 | P1 严重缺陷清零 | SSRF / fetch 加固 / 引擎测试 / 部署说明 | `url-guard.ts`、测试套件、README | ✅ |
| Phase 4 | P2/P3 治理与同步 | 反模式、占位节点标注、版本钉死、文档索引 | 代码 + 全量文档同步 | ✅ |
| Phase 5 | 全量复验 | lint / tsc / test / build / API 黑盒 | 02-执行日志 + 03-总结文档 | ✅ |

## 三、详细任务分解

### Task 1.1：建立文档与日志机制

**目标**：按《YYC3-团队通用-开发文档》§2 建立会话目录 00/01/02/03 四件套；新增运行时 JSON Lines 结构化日志模块并支持敏感字段脱敏。

**验收标准**：
- [x] 上文调研报告完整落盘至 `00-项目现状审核报告.md`
- [x] 本文档（01）、执行日志（02）、总结同步（03）齐全
- [x] `lib/logger.ts` 提供 debug/info/warn/error 分级、requestId、密钥自动脱敏
- [x] 项目级 `CHANGELOG.md` 与 `docs/YYC3-文档与日志机制规范.md` 建立

**依赖关系**：无
**风险点**：文档中不得写入真实密钥 → 统一使用 `${ENV_VAR_NAME}` 占位符
**完成标记**：✅ 已完成

### Task 2.1：修复 VM 沙箱顶层 return（P0-1 / P0-2 同源）

**目标**：使 `conditional` 节点与按 UI 提示书写 `return` 的 `javascript` 节点均可正常执行，同时保留尾表达式兼容。

**验收标准**：
- [x] `safeExecute("return 1+1")` 返回 2
- [x] `safeExecute("input1 + ' x'")` 仍返回尾表达式结果
- [x] 宿主内置对象不再注入沙箱上下文（消除越狱通道）
- [x] 5s 超时选项保留、黑名单与代码长度限制通过用例验证（5s 耗时用例列入后续压测）

**依赖关系**：无
**风险点**：条件节点由引擎拼接 `return ${condition}`，必须保持兼容
**完成标记**：✅ 已完成

### Task 2.2：执行 API 鉴权与限流（P0-3）

**目标**：`POST /api/execute-workflow` 支持可选令牌鉴权 + 按 IP 滑动窗口限流。

**验收标准**：
- [x] 设置 `WORKFLOW_API_TOKEN` 后，缺少/错误令牌返回 401
- [x] 超过 `WORKFLOW_RATE_LIMIT_MAX` 返回 429 且携带 `Retry-After`
- [x] 未配置令牌时本地开发不受影响（显式记录降级告警）
- [x] 前端可携带令牌，401/429 有可读错误提示

**依赖关系**：Task 1.1（日志）
**风险点**：令牌不可硬编码；前端令牌仅适用于内部部署，生产须换会话鉴权
**完成标记**：✅ 已完成

### Task 3.1：SSRF 与出站请求加固（P1）

**目标**：URL 校验升级为 DNS 解析后 IP 判定，禁止重定向，补超时与响应体上限。

**验收标准**：
- [x] `169.254.169.254`、`0.0.0.0`、`::1`、`2130706433`、私有域名均被拒
- [x] 302 跳转被拒绝；非 JSON / 超大响应被拒绝；超时被中断
- [x] 变量插值 `$&` 等特殊序列不再破坏结果

**依赖关系**：Task 2.2
**风险点**：DNS rebinding TOCTOU 需文档化残留风险与出口白名单建议
**完成标记**：✅ 已完成

### Task 3.2：执行引擎回归测试（P1）

**目标**：补齐 `route.ts` 与 `safe-executor.ts` 零覆盖。

**验收标准**：
- [x] 引擎正向链路、条件 TRUE/FALSE、错误冒泡、401/429 全部有用例
- [x] 沙箱、URL 网关、日志脱敏均有单测
- [x] `vitest.config.ts` coverage 纳入 `app/api/**`
- [x] 测试总数 > 135 且全绿

**依赖关系**：Task 2.1 / 2.2 / 3.1
**风险点**：测试中 mock AI SDK，避免真实外网调用与费用
**完成标记**：✅ 已完成

### Task 4.1：P2/P3 治理与文档同步

**目标**：消除 handleRun DOM 反模式、空 catch；占位节点显式标注；依赖版本钉死；README/文档索引/04-测试审核阶段同步。

**验收标准**：
- [x] `page.tsx` 不再使用 `document.querySelector(...).click()`
- [x] README 版本号、功能状态矩阵、部署限制与实测一致
- [x] `package.json` 无 `latest` 依赖，`pnpm-lock.yaml` 同步
- [x] `docs/README.md` 失效链接修复，新增会话目录与机制文档索引

**依赖关系**：Phase 2/3
**风险点**：`NODE_TYPES_LIST` 复核为刻意 10 项，不得误改（已有测试断言）
**完成标记**：✅ 已完成

### Task 5.1：全量质量门禁复验

**目标**：`pnpm lint` / `npx tsc --noEmit` / `pnpm test` / `pnpm build` 全绿，并做 API 级黑盒复测。

**验收标准**：
- [x] 4 项门禁 0 错误 0 警告
- [x] API 正向 + 反向用例复测通过
- [x] 02/03 文档记录实测数据与残留风险

**依赖关系**：Phase 2/3/4
**完成标记**：✅ 已完成
