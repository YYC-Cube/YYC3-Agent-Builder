## 关键决策记录

| 决策 | 背景 | 选择 | 原因 |
| --- | --- | --- | --- |
| 沙箱双模式执行 | 顶层 `return` 与尾表达式完成值都要兼容 | V8 编译期探测 `Illegal return statement` 后切换函数模式 | 无需正则启发式、不会重复执行用户代码、兼容 conditional 的 `return <expr>` 拼接 |
| 输入以序列化字符串传入上下文 | 宿主内置对象可被 `constructor.constructor` 越狱 | 沙箱仅暴露 `__inputsJSON` 字符串，JSON 等由上下文自身提供 | 从根本上移除宿主对象引用 |
| 令牌未配置时开发态放行 | 强制鉴权会中断本地开发与现有测试 | `WORKFLOW_API_TOKEN` 可选 + 默认限流 | 兼顾开箱即用与生产可加固；文档明确生产必须配置 |
| SSRF 采用解析后 IP 判定 | 前缀字符串匹配可被多种 IP 写法绕过 | DNS `lookup(all)` 后逐地址判定 + 禁重定向 + 方法白名单 | 覆盖云元数据与 IPv6 映射；残留 DNS rebinding 由出口白名单兜底 |
| `NODE_TYPES_LIST` 不改 | 初判「缺 2 项」 | 复核为面板刻意 10 项（已有测试断言） | 以代码与测试为准，撤销误判，避免制造回归 |
| 部署主方案选 Docker standalone | GH Pages 无 Node runtime；Vercel 有函数超时与计费约束 | 主 Docker，备 Vercel | 可控运行时、可接 Redis/反代/内网，SSE 可配置禁缓冲 |
| 限流选 ZSET 滑动窗口 | 固定窗口在边界会双倍突发 | Redis ZSET + 单次 EVAL | 精度到毫秒，避免竞态与边界突发 |
| 持久化选 Postgres + Drizzle | 图是 JSON 文档但账号/运行需强一致 | JSONB + 关系表 | 一套库满足图、版本、运行记录；SQL 透明便于审计 |
| 账号选 Better Auth | Auth.js 进入维护模式 | Better Auth（自托管） | 数据自有，后续可加组织/SSO 插件 |
| 结构化输出用 `Output.object` | AI SDK 7 已移除 `generateObject` | `generateText({ output })` | 与官方 v7 API 对齐，schema 直接参与约束与校验 |
| 应用落位 NAS V3 | 7×24 常开、NVMe、贴近 Redis | Docker compose，仅绑 Tailscale | 不依赖笔记本电源状态 |
| PG 数据盘迁 V3（已定案） | V2 为 HDD RAID6，随机写延迟高 | PGDATA/WAL 放 V3，V2 只放备份 | 避免数据库成为 P95 瓶颈；执行单 006 |
| PG 主备方向（已定案） | Mac 休眠/macOS 更新会中断写入 | NAS 主、Mac 备（DR/只读），双端 5433 | 生产可用性优先；已同步 env 模板与切换手册 |
| 备份必须异机 | V1/V2 同属一个 RAID6 池 | V2 短期 + Mac 外置 + 对象存储 | 防池故障同时丢模型、库与备份 |

## 遇到的问题与解决方案

| 问题 | 解决方案 | 经验教训 |
| --- | --- | --- |
| `vm.Script` 构造不接受 `displayErrors` 选项（tsc TS2353） | 移到 `runInContext` 运行选项 | 区分编译期与运行期选项 |
| Vitest mock `node:dns/promises` 报「No default export」 | factory 返回 `default` | Node 内置模块走 CJS interop |
| mock 生效但 `lookup` 仍走真实 DNS | 把同一 `vi.fn` 同时挂到 `default.lookup` 与命名导出，并去掉 `restoreAllMocks` | Node 内置模块成员可能从 default 命名空间解析；`restoreAllMocks` 会还原模块 mock |
| `NODE_TYPES_LIST` 初判缺项 | 复核测试断言后撤销 | 不靠清单表面差异下结论，先看测试意图 |
