## 二、表设计

### 账号（Better Auth 1.7.x 兼容）

| 表 | 关键列 | 约束 |
| --- | --- | --- |
| `user` | `id`, `name`, `email`, `emailVerified`, `image`, `createdAt`, `updatedAt` | `email` 唯一 |
| `session` | `id`, `userId`, `token`, `expiresAt`, `ipAddress`, `userAgent` | `token` 唯一；`userId` 级联删除 |
| `account` | `id`, `userId`, `accountId`, `providerId`, `password` 等 | `(providerId, accountId)` 唯一 |
| `verification` | `id`, `identifier`, `value`, `expiresAt` | `identifier` 索引 |

> 表名/列名严格遵循 Better Auth 默认（camelCase）。**不要**改成 `users`/`user_id`，否则需在 `betterAuth` 配置里同步 `modelName`/`fields`，否则运行期 schema 校验失败。

### 业务

| 表 | 关键列 | 索引 |
| --- | --- | --- |
| `workflows` | `owner_id`, `name`, `graph`(JSONB), `version`, `is_public` | `(owner_id, updated_at desc)`、`GIN(graph)` |
| `workflow_versions` | `workflow_id`, `version`, `graph`, `created_by` | `(workflow_id, version)` 唯一 |
| `runs` | `workflow_id`, `user_id`, `status`, `started_at`, `finished_at`, `token_usage`, `cost_usd` | `(workflow_id, started_at desc)`、`(user_id, started_at desc)`、`status` |
| `run_events` | `run_id`, `seq`, `node_id`, `type`, `payload` | `(run_id, seq)` 唯一 |

- `graph` 直接存 React Flow 的 `{ nodes, edges, viewport }`，避免拆表；
- `run_events` 与 SSE 事件一一对应，可按 `run_id` 顺序回放；
- `updated_at` 由触发器维护（`user`/`session`/`account`/`verification`/`workflows`）。

## 三、执行顺序

```bash
# 0. 备份（生产必须先做）
pg_dump "$DATABASE_URL" -Fc -f /backup/yyc3_agent-before-phase-a-$(date +%F).dump

# 1. 生成/校验迁移（改 schema 后）
pnpm db:generate
pnpm db:check

# 2. 在演练库先跑（yyc3-77 或本地 PG15）
DATABASE_URL=postgres://.../yyc3_agent_drill pnpm db:migrate

# 3. 生产应用
pnpm db:migrate

# 4. 不用 drizzle-kit 时的手工路径
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f db/migrations/0000_black_medusa.sql
```

> `db:migrate` 必须设置 `DATABASE_URL`；`db:generate` / `db:check` 不需要连接。

## 四、验证 SQL

```sql
-- 表清单
select table_name from information_schema.tables
where table_schema = 'public' order by 1;

-- 索引
select indexname, indexdef from pg_indexes
where schemaname = 'public' and tablename in ('workflows','runs','run_events')
order by 1;

-- 枚举
select enumlabel from pg_enum e join pg_type t on t.oid = e.enumtypid
where t.typname = 'run_status' order by enumsortorder;

-- 触发器
select event_object_table, trigger_name from information_schema.triggers
where trigger_schema = 'public' order by 1;

-- GIN 索引是否生效（示例）
explain select id from workflows where graph @> '{"nodes":[]}'::jsonb;
```

# 2. 删除新增表（按依赖倒序；确认无数据依赖）
psql "$DATABASE_URL" <<'SQL'
drop table if exists run_events;
drop table if exists runs;
drop table if exists workflow_versions;

drop table if exists verification;

## 六、阶段 B 已实现（2026-11-11）

### 6.1 认证与账号安全

- 服务端：`lib/auth.ts`（Better Auth 1.7.20 + Drizzle adapter + `nextCookies`）
- 路由：`app/api/auth/[...all]/route.ts`（GET/POST）
- 客户端：`lib/auth-client.ts`
- 页面：
  - `app/login/page.tsx`：邮箱 + 密码登录/注册；未验证邮箱时提示并支持重发
  - `app/verify-email/page.tsx`：读取 `?token=` 调用 `verifyEmail`
  - `app/forgot-password/page.tsx`：申请重置链接（通用响应，防账号枚举）
  - `app/reset-password/page.tsx`：读取 `?token=` / `?error=INVALID_TOKEN`，设置新密码
- 邮件：`lib/email.ts`（nodemailer + SMTP）；未配置 SMTP 时开发环境打印预览，生产直接报错
- 环境变量：
  ```bash
  BETTER_AUTH_SECRET=$(openssl rand -base64 32)
  BETTER_AUTH_URL=http://localhost:3146
  NEXT_PUBLIC_APP_URL=http://localhost:3146
  SMTP_HOST=smtp.example.com
  SMTP_PORT=587
  SMTP_USER=
  SMTP_PASS=
  SMTP_FROM="YYC³ <no-reply@yyc3.vip>"
  ```
  生产改为 `https://agent.yyc3.vip`。

**安全策略**：

| 项 | 实现 |
| --- | --- |
| 强制邮箱验证 | `emailAndPassword.requireEmailVerification` + `emailVerification.sendOnSignUp/sendOnSignIn` |
| 重置后吊销会话 | `revokeSessionsOnPasswordReset: true` |
| 防暴力破解 | `rateLimit`：登录 10/60s、注册 5/60s、重置/重发 5/60s |
| 防账号枚举 | 忘记密码始终返回通用提示；登录 403 才提示未验证 |
| 防时序攻击 | 发信回调不 `await`，失败仅记录日志 |
| 防开放重定向 | 生产 `trustedOrigins` 仅允许 `BETTER_AUTH_URL` |
| 密码长度 | 8–128；重置 token 由 Better Auth 管理 |

### 6.2 工作流 CRUD

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/workflows` | 当前用户的工作流列表（最多 100，按更新时间倒序） |
| `POST` | `/api/workflows` | 创建；自动写 `workflow_versions` v1 |
| `GET` | `/api/workflows/:id` | 读取单条（归属校验） |
| `PATCH` | `/api/workflows/:id` | 改名/图/公开标记；图变化时版本 +1 并写历史 |
| `DELETE` | `/api/workflows/:id` | 删除（级联 runs/versions） |

- 所有接口要求登录，未登录 401；非法 UUID/非本人 404；zod 校验失败 400。
- 校验：`lib/workflows/validation.ts`（name ≤120、节点 ≤200、边 ≤500）。
- 数据访问：`lib/workflows/repository.ts`（全部带 `owner_id` 条件，防越权）。

### 6.3 执行落库

`POST /api/execute-workflow` 支持可选 `workflowId`：

- 会话用户 + `workflowId`：校验归属后创建 `runs(status=running)`，每个 SSE 事件按 `seq` 写 `run_events`，结束更新 `succeeded/failed`；
- 未登录或未传 `workflowId`：保持原行为（令牌/IP 限流，不落库）；
- 数据库写入失败 **不影响执行**（记录告警，SSE 继续）；
- 鉴权双模：会话用户跳过执行令牌，按 `user:<id>` 限流；无会话时仍按令牌/IP。

### 6.4 前端

- 头部新增「云端」菜单：保存/更新、列表加载、删除；执行面板自动携带 `workflowId`；
- 未登录时菜单引导至 `/login`；
- 本地 `localStorage` 草稿仍保留，作为离线兜底。

### 6.5 本地 E2E 验证（2026-11-11）

在 `/tmp` 临时 PG17（端口 55433，独立库 `yyc3_agent_dev`）执行迁移并跑通全链路，**未触碰 5433 的 Mac 备库**：

| 步骤 | 结果 |
| --- | --- |
| `pnpm db:migrate` | 成功，`public` 下 **8 张表** |
| 注册 `e2e@yyc3.vip` | 200，`emailVerified=false`，开发日志输出验证链接 |
| 未验证登录 | **403** `EMAIL_NOT_VERIFIED` |
| 打开验证链接 | 200，`emailVerified=true` |
| 验证后登录 | 200，写入会话 cookie |
| 创建 `POST /api/workflows` | **201**，写入 `workflows` + `workflow_versions` v1 |
| 执行 `POST /api/execute-workflow`（带 `workflowId`） | SSE 完整；`runs=succeeded`，`run_events` seq 1–3 |
| 申请重置密码 | 200，开发日志输出 `/api/auth/reset-password/{token}` |
| 重置密码 | 200；旧密码登录 **401**，新密码 **200** |
| 重置后旧会话访问 `/api/workflows` | **401**（`revokeSessionsOnPasswordReset` 生效） |

> 临时库仅用于本地验证；生产 PG15 仍需在维护窗口执行 `db:migrate`。SMTP 未配置时开发环境仅打印预览，生产会拒绝发信。

## 八、注意事项

1. **不要**在已应用的迁移上直接改 SQL；新增 `db:generate` 迁移。
2. Better Auth 表必须与 `betterAuth()` 配置一致；启用 joins 时确保 relations 通过 adapter 的 `schema` 传入。
3. `user` / `session` 是保留字，手写 SQL 必须加双引号。
4. 生产库只允许 `yyc3_app` 最小权限账号执行 DML；DDL 用迁移账号，迁移后回收。
5. 大表加索引使用 `CREATE INDEX CONCURRENTLY`（单独迁移，不能放在事务里）。
6. 迁移前确认备库复制追平，迁移后确认 `pg_stat_replication` 正常。
7. `BETTER_AUTH_SECRET` 必须使用 32 字节以上随机值，轮换会使现有会话失效。
8. 云端 URL 必须与 `BETTER_AUTH_URL` 一致，否则 cookie/回调会失败。
9. `run_events.payload` 当前保存完整事件（含节点输出）；图片/音频 data URL 会放大表体积，阶段 C 改为对象存储引用。
