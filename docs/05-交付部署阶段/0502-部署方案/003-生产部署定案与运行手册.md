## 一、定案

| 项 | 结论 |
| --- | --- |
| **主方案** | Docker + Next.js `output: "standalone"`，前置 nginx / 云 LB |
| **备选** | Vercel（最快上线，但函数超时/计费需评估） |
| **排除** | GitHub Pages（无法运行 `/api/*` 动态路由与 SSE） |
| **域名** | `agent.yyc3.vip`（DNS 指向主方案入口；`public/CNAME` 仅为历史遗留） |

## 二、环境变量矩阵

| 变量 | 生产必配 | 说明 |
| --- | --- | --- |
| `GOOGLE_GENERATIVE_AI_API_KEY` | ✅ | Gemini / 图像 |
| `OPENAI_API_KEY` | 按需 | GPT / TTS / Embeddings |
| `ANTHROPIC_API_KEY` / `XAI_API_KEY` | 按需 | 其他模型 |
| `WORKFLOW_API_TOKEN` | ✅ | 执行 API 令牌；未配置将开放执行（仅开发） |
| `REDIS_URL` | NAS 部署必配 | 本地/自建 Redis（如 `redis://redis:6379/0`），优先级高于 REST |
| `DATABASE_URL` | 阶段 A 启用 | PG15 主库：**NAS `100.65.172.88:5433`**（已定案） |
| `DATABASE_REPLICA_URL` | 可选 | PG15 备库：**Mac `100.87.159.21:5433`**（报表/DR） |
| `UPSTASH_REDIS_REST_URL` / `_TOKEN` | 托管多实例必配 | 共享限流（兼容 `KV_REST_API_*`） |
| `RATE_LIMIT_FAIL_MODE` | 可选 | `open`（默认）/ `closed` |
| `WORKFLOW_RATE_LIMIT_MAX` / `WINDOW_MS` | 可选 | 默认 20 次 / 60000ms |
| `WORKFLOW_HTTP_TIMEOUT_MS` / `MAX_BYTES` | 可选 | 出站 10s / 1 MiB |
| `LOG_LEVEL` | ✅ | `info`（生产）/ `warn`（降噪） |
| `NEXT_SERVER_ACTIONS_ENCRYPTION_KEY` | 多实例必配 | 统一 Server Action 加密密钥 |
| `PORT` / `HOSTNAME` | 容器内 | `3000` / `0.0.0.0` |

> 密钥只允许存在于部署平台的 Secret / `.env.production`，禁止写入镜像、文档或日志。

## 三、路径 A：Docker standalone（主方案）

```bash
# 1. 构建
docker build -t yyc3-agent-builder:0.1.2 .

# 2. 运行（推荐 --read-only + tmpfs）
docker run -d --name yyc3-agent \
  -p 3000:3000 \
  --env-file .env.production \
  --read-only --tmpfs /tmp \
  --restart unless-stopped \
  yyc3-agent-builder:0.1.2

# 3. 健康检查
curl -fsS http://127.0.0.1:3000/api/health
```

镜像已包含 `HEALTHCHECK`（30s 间隔、25s 启动宽限）。`Dockerfile` 使用 Node 22 + pnpm，多阶段构建，运行用户为非 root `nextjs`。

**NAS 落位（yyc3-45 / Docker V3）**：推荐直接用仓库内编排文件，app 只绑定 Tailscale 地址，Redis 与应用同机：

```bash
cd deploy
cp .env.production.example .env.production   # 填 WORKFLOW_API_TOKEN 与 AI Key
docker compose -f docker-compose.prod.yml up -d --build
curl -fsS http://100.65.172.88:3000/api/health   # rateLimitStore 应为 redis
```

拓扑、PG 主备方向、数据盘选型与备份策略见 [集群拓扑与部署映射](../../06-运维保障阶段/0601-运维策略/004-集群拓扑与部署映射.md)。

**nginx 关键配置**（SSE 必须禁缓冲）：

```nginx
location /api/execute-workflow {
  proxy_pass http://127.0.0.1:3000;
  proxy_http_version 1.1;
  proxy_set_header Host $host;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  proxy_buffering off;
  proxy_cache off;
  proxy_read_timeout 120s;
  chunked_transfer_encoding on;
}

location / {
  proxy_pass http://127.0.0.1:3000;
  proxy_http_version 1.1;
  proxy_set_header Host $host;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

## 四、路径 B：Vercel（备选）

1. 导入仓库，Framework 选择 Next.js，构建命令 `pnpm build`。
2. 配置环境变量（同上矩阵），`WORKFLOW_API_TOKEN` 必配。
3. `maxDuration = 30` 已由路由导出；更长工作流需升级计划或拆分。
4. 多实例限流必须使用 Upstash（Vercel 函数实例不共享内存）。

## 五、发布与回滚

```bash
# 发布前四门禁
pnpm lint && npx tsc --noEmit && pnpm test && pnpm build

# 滚动发布
docker tag yyc3-agent-builder:0.1.2 yyc3-agent-builder:current
docker compose up -d --no-deps --build app

# 回滚
docker tag yyc3-agent-builder:<previous> yyc3-agent-builder:current
docker compose up -d --no-deps app
```

**停机**：编排平台发送 `SIGTERM`，给 10–30s 排水；Next.js 会完成在途请求与 `after()`。

## 六、部署检查清单

- [ ] `WORKFLOW_API_TOKEN` 已配置且未进入镜像层
- [ ] `/api/health` 返回 200，`rateLimitStore` 与预期一致
- [ ] SSE 首包 < 1s（`curl -N` 观察逐行输出）
- [ ] 反代/LB 已关闭缓冲（`X-Accel-Buffering: no` 生效）
- [ ] 多实例：`NEXT_SERVER_ACTIONS_ENCRYPTION_KEY` 一致、限流走 Redis
- [ ] 日志为 JSON Lines，且不含密钥/完整 payload
- [ ] 备份与回滚镜像可用

## 七、常见故障

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| SSE 一次性输出而非逐条 | 反代/LB 缓冲 | 关闭 `proxy_buffering`，确认 `X-Accel-Buffering: no` |
| 多实例限流不准 | 仍在使用内存存储 | 配置 Upstash 环境变量，检查 `/api/health` |
| 401 全量失败 | 前端未带令牌 | 执行面板输入令牌或配置 `NEXT_PUBLIC_WORKFLOW_API_TOKEN` |
| 429 频繁 | 多实例共享配额被单 IP 打满 | 调整 `WORKFLOW_RATE_LIMIT_MAX`，网关加白/黑名单 |
| 镜像启动即退出 | 未拷贝 `public` / `.next/static` | 使用本仓库 Dockerfile，勿手写简化版 |
