> 以下为**对接建议**，干系人角色（C-09）、发布周期（C-10）、反馈渠道（C-11）待正式确认。

| 场景 | 对接对象（建议） | 输入 | 输出 |
| ---- | ---- | ---- | ---- |
| 确认清单闭环 | 产品/架构/运维/维护者（按 C 编号） | 本报告 C-01~15 | 书面确认，回填采集报告 |
| 安全闸口决策 | 安全 + 产品 | C-04/C-13 部署与鉴权结论 | 鉴权方案（env 注入密钥） |

## 5. 验收校验提示词（供二次复核 / 闭环整改）

> 将以下提示词交给复核方（或下一轮 AI），可独立复验本次交付并驱动整改。

```
【二次复核提示词 — YYC³ Agent Builder 首次调研】
你Independent审查者。请对 /Users/yanyu/YYC-Cube/personal/YYC3-Agent-Builder 执行只读复核，禁止修改文件，逐项输出 PASS/FAIL 与证据：

1. 门禁复验：运行 pnpm lint、pnpm exec tsc --noEmit、pnpm test、pnpm exec next build，报告退出码与测试数（基线应为 lint0/tsc0/test147/build0）。任一非0即 FAIL。
2. SSRF 修复核验：读取 app/api/execute-workflow/route.ts 的 validateUrl，确认拦截 169.254./::1/::/fc00:/fd00:/fe80:；运行 __tests__/lib/ssrf-validation.test.ts 确认 12 条通过。
3. 确认清单核验：读取 docs/YYC3-团队通用-标规文档/YYC3-首次调研-全景信息采集报告.md，确认 C-01~15 齐全且每项有确认路径；核验报告未把待确认项写成事实。
4. 六维诊断核验：读取穿透式深度分析报告，确认 6 个维度均含「现状/问题/影响」三层。
5. 测试方案核验：读取测试验证方案与结论，确认含正向+反向用例、优先级、预期结果、边界清单、覆盖建议、环境兼容、通过/失败规则。
6. 分级与修复核验：读取问题分级与修复设计，确认 P0-P3 分级、本次执行项（F1~F4）与未执行项原因齐备。
7. 硬约束红线核验：
   - grep 是否引入 supabase/firebase（应为空）
   - grep 硬编码 100.x Tailscale IP / 密钥 token（应为空；SSRF 黑名单字面量不计）
   - 确认 pnpm-workspace.yaml 未被改为非占位内容（本次应保持原样）
   - 确认未改包管理器（package.json/lockfile 无异常）
   - 确认 lib 目录无 @/components 引用（单向依赖）
8. 文档落盘核验：确认两个目录共 7 份 .md 存在且 front matter 合法（tags 为 YAML 序列、file 与文件名一致、含品牌标头与居中标尾）。
9. 对齐状态核验：确认交付状态标记为「已完成 ✅」且与 §1 一致。
10. 失败判定：以上任一 FAIL，输出具体整改建议并停闸，禁止建议绕过门禁或安全校验。

输出格式：| 项 | PASS/FAIL | 证据 | 整改建议 |
```

## 6. 闭环整改流程

1. 复核方执行 §5 提示词，产出 PASS/FAIL 表。
2. FAIL 项按《优化建议与规划》的停闸规则处理：先修复 → 红灯测试 → 门禁全绿 → 复验。
3. 确认清单项由责任方书面确认后，回填采集报告并更新问题分级状态列。
4. 每轮整改后更新本手册 §1 交付结论与 front matter `updated`/`version`。
