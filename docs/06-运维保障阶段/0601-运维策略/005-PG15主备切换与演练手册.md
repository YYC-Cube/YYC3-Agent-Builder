## 一、角色与端口（已定案）

| 角色 | 主机 | Tailscale | 端口 | 数据目录 | 服务 |
| --- | --- | --- | --- | --- | --- |
| **主库（Primary）** | yyc3-45 NAS | `100.65.172.88` | 5433 | V3 NVMe `$V3_MOUNT/pgdata/15/main`（迁移后） | `postgresql@15-main` |
| **备库（Standby）** | yyc3-22 Mac | `100.87.159.21` | 5433 | 外置 NVMe `/opt/pgdata/15/main` | `postgresql@15-main` |
| 应用 | yyc3-45 Docker | `100.65.172.88:3000` | 3000 | — | compose `app` |

> 端口约定：**两台主机各监听 5433**。PgBouncer 如需启用，另用 6432，不改变本约定。若 PG 跑在容器内，把 `pg_ctl`/`systemctl` 换成 `docker exec`，数据目录相应调整。

## 二、前置条件（首次搭建/演练前检查）

```conf
# 主库 postgresql.conf 关键项
wal_level = replica
max_wal_senders = 10
max_replication_slots = 10
wal_keep_size = 2GB
wal_log_hints = on          # pg_rewind 必需（或启用 checksums）
hot_standby = on
synchronous_commit = remote_write
```

```conf
# 主库 pg_hba.conf（仅 tailnet）
host    replication   repl   100.64.0.0/10   scram-sha-256
host    all           yyc3_app 100.64.0.0/10 scram-sha-256
```

```bash
# 主库创建复制账号与槽
createuser -p 5433 -U postgres --replication repl
psql -p 5433 -U postgres -c "select pg_create_physical_replication_slot('yyc3_22');"
```

- 两端 PG **大版本与次版本一致**（15.x），`pg_rewind` 已安装；
- 两端 NTP/chrony 时间同步；
- Mac 备库磁盘 ≥ 主库实际数据量（V3 1.9T 足够）；
- 备份任务已覆盖主库（V2 归档 + Mac 外置 + 对象存储）。

## 三、日常巡检（每日/告警触发）

```bash
# 主库：复制连接与同步状态
psql -h 100.65.172.88 -p 5433 -U postgres -c \
 "select client_addr, application_name, state, sync_state,
         sent_lsn, replay_lsn, write_lag, flush_lag, replay_lag
  from pg_stat_replication;"

# 备库：是否处于恢复、回放延迟
psql -h 100.87.159.21 -p 5433 -U postgres -c \
 "select pg_is_in_recovery(),
         now() - pg_last_xact_replay_timestamp() as replay_lag,
         pg_last_wal_receive_lsn(), pg_last_wal_replay_lsn();"

# 槽保留情况（防止 WAL 堆积）
psql -h 100.65.172.88 -p 5433 -U postgres -c \
 "select slot_name, active, restart_lsn, pg_size_pretty(pg_wal_lsn_diff(pg_current_wal_lsn(), restart_lsn)) as retained
  from pg_replication_slots;"
```

**告警阈值**：`replay_lag > 5s` 持续 1 分钟；`state != streaming`；槽保留 > 5GB；备库 `pg_is_in_recovery() = false` 且主库仍在线（脑裂信号）。

## 四、计划内切换（Switchover，可回滚）

> 命令中的 `$V3_MOUNT` 需按 [006 执行单](006-PGDATA迁移至V3执行单.md) 的实测挂载点设置（示例 `/mnt/yyc3-v3`）。
>
> 目标：零数据丢失，应用短暂只读（预计 30–60s）。建议在维护窗口执行。

1. **冻结写入**（可选但推荐）：
   ```sql
   -- 主库
   alter system set default_transaction_read_only = on;
   select pg_reload_conf();
   ```
   或在应用层把 `DATABASE_URL` 指向只读副本/停写。
2. **确认备库追平**：
   ```bash
   psql -h 100.87.159.21 -p 5433 -U postgres -c \
    "select pg_last_wal_receive_lsn() = pg_last_wal_replay_lsn() as caught_up;"
   ```
   必须为 `t`，且 `replay_lag < 1s`。
3. **提升备库**（Mac，备库需保持运行）：
   ```bash
   ssh YYC3@100.87.159.21
   sudo -u postgres pg_ctl promote -D /opt/pgdata/15/main
   psql -p 5433 -U postgres -c "select pg_is_in_recovery();"   -- 期望 f
   ```
4. **切换应用**：
   ```bash
   cd /opt/yyc3/deploy
   sed -i 's#@100.65.172.88:5433#@100.87.159.21:5433#' .env.production
   docker compose -f docker-compose.prod.yml up -d app
   curl -fsS http://100.65.172.88:3000/api/health
   ```
   > 若使用稳定的 `pg-primary.yyc3.vip` 域名，只需切换 DNS/反代，不必改 env；当前按 IP 直连，需改 env。
5. **旧主回加入**（NAS 作为新备库）：
   ```bash
   ssh YYC3@100.65.172.88
   sudo systemctl stop postgresql@15-main
   # 干净关闭优先用 pg_basebackup 重建；有分叉时用 pg_rewind
   sudo -u postgres pg_rewind --target-pgdata=$V3_MOUNT/pgdata/15/main \
     --source-server="host=100.87.159.21 port=5433 user=postgres"
   sudo -u postgres touch $V3_MOUNT/pgdata/15/main/standby.signal
   # postgresql.auto.conf 写入 primary_conninfo（见 §六）
   sudo systemctl start postgresql@15-main
   ```
6. **解除只读**（若第 1 步设置过）：
   ```sql
   alter system set default_transaction_read_only = off;
   select pg_reload_conf();
   ```
7. **验证**：新主可写、新备 `pg_is_in_recovery()=t`、应用健康、SSE 正常。

## 五、故障切换（Failover，主库不可用）

> 先确认是「真故障」而非「网络分区」，否则提升备库会造成双主。

1. **确认主库状态**：
   ```bash
   tailscale ping yyc3-45
   pg_isready -h 100.65.172.88 -p 5433
   ssh YYC3@100.65.172.88 'systemctl status postgresql@15-main' || echo "HOST_UNREACHABLE"
   ```
   - 主机可达但 PG 挂 → 可尝试重启；重启失败再提升；
   - 主机不可达且短时间无法恢复 → 提升备库。
2. **提升备库（Mac，备库需保持运行）**：
   ```bash
   sudo -u postgres pg_ctl promote -D /opt/pgdata/15/main
   psql -p 5433 -U postgres -c "select pg_is_in_recovery();"   -- f
   ```
3. **切换应用**：同 §四 第 4 步；`DATABASE_URL` 指向 `100.87.159.21:5433`。
4. **记录时间线**：故障开始、提升时间、应用恢复时间、最后确认的 `replay_lsn`。
5. **旧主恢复后**：**不要直接启动为主库**。先按 §六 以 `pg_rewind` 回加入为备库；确认 `pg_is_in_recovery()=t` 后才允许加入集群。

**RTO/RPO 目标（手工切换）**：RTO ≤ 15 分钟；RPO ≤ 1 秒（`synchronous_commit=remote_write`）。若要求 RTO < 1 分钟，需引入 Patroni + etcd（3 节点见证）。

## 六、备库回加入（pg_rewind）

```bash
# 1. 停旧实例
sudo systemctl stop postgresql@15-main

# 2. 回滚分叉（要求 wal_log_hints=on 或 checksums）
sudo -u postgres pg_rewind \
  --target-pgdata=$V3_MOUNT/pgdata/15/main \
  --source-server="host=100.87.159.21 port=5433 user=postgres" \
  --progress

# 3. 在新主（Mac）上为旧主创建复制槽
psql -h 100.87.159.21 -p 5433 -U postgres \
  -c "select pg_create_physical_replication_slot('yyc3_45');"

# 4. 标记为备库
sudo -u postgres touch $V3_MOUNT/pgdata/15/main/standby.signal

# 5. 配置主库连接（postgresql.auto.conf）
cat >> $V3_MOUNT/pgdata/15/main/postgresql.auto.conf <<'EOF'
primary_conninfo = 'host=100.87.159.21 port=5433 user=repl application_name=yyc3-45 password=CHANGE_ME'
primary_slot_name = 'yyc3_45'
recovery_target_timeline = 'latest'
EOF

# 6. 启动并验证
sudo systemctl start postgresql@15-main
psql -p 5433 -U postgres -c "select pg_is_in_recovery();"   -- t
```

> 若 `pg_rewind` 报「no rewind needed」或失败，改用 `pg_basebackup -R` 全量重建备库（更稳妥，耗时取决于数据量）。

## 八、演练验收（每季度，yyc3-77 可参与）

| 步骤 | 验收标准 |
| --- | --- |
| 1. 模拟主库宕机（停 NAS PG） | 监控告警在 1 分钟内触发 |
| 2. 提升 Mac 备库 | `pg_is_in_recovery()=f`，提升耗时 ≤ 5 分钟 |
| 3. 切换应用 | 健康检查 200，工作流执行成功 |
| 4. 旧主回加入 | 新备 `pg_is_in_recovery()=t`，`replay_lag < 1s` |
| 5. 数据一致性 | 演练前后行数/校验和一致，无重复主键 |
| 6. 复盘 | 输出时间线、RTO/RPO 实测、改进项 |

## 九、常见故障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 备库 `state=startup` 长时间不变 | `primary_conninfo` 错误/认证失败 | 检查 `pg_hba`、密码、`application_name`；看 `pg_log` |
| `pg_rewind` 报找不到 WAL | `wal_log_hints=off` 且未开 checksums | 开启 `wal_log_hints` 后重建，或直接 `pg_basebackup -R` |
| 提升后备库无写权限 | 仍处于 recovery / 只读参数 | `pg_is_in_recovery()`、`default_transaction_read_only` |
| 双主 | 网络分区后误提升 | 立即停其中一个；以 `pg_controldata` 的 timeline 判定；从备份恢复 |
| 槽导致 WAL 堆积 | 备库长期离线 | 删除失效槽或重建备库；监控 `retained` |
| 应用连接旧主 | 只改了 env 未重启 / 连接池缓存 | 重启 app；必要时重启 PgBouncer |

## 十、安全与边界

- 5433 **只对 tailnet 开放**；`pg_hba.conf` 仅允许 `100.64.0.0/10`；
- 复制账号独立、最小权限；密码放 Secret，不入库不入文档；
- 提升操作需双人复核（至少在生产环境）；
- 所有切换必须记录到运维日志，并同步 `docs/agent-builder-hunyuan-20261111/02-执行日志与进度跟踪.md`。
