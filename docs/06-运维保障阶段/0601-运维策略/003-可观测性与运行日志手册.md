## 一、日志契约

`lib/logger.ts` 输出单行 JSON（stdout/stderr），字段固定：

| 字段 | 说明 |
| --- | --- |
| `ts` | ISO 时间戳 |
| `level` | `debug / info / warn / error` |
| `module` | `execute-workflow` / `workflow-engine` / `api-guard` / `rate-limit` |
| `requestId` | 单次请求关联 ID（当前为进程内生成，接入网关后可透传） |
| `message` | 稳定短句，便于聚合 |
| 业务字段 | `nodeId`、`nodeType`、`clientId`、`error` 等 |

**脱敏红线**：`token / secret / password / apiKey / authorization / cookie` 等字段自动替换为 `[REDACTED]`；单个值截断 2000 字符、嵌套深度 4 层；不得记录完整 prompt、模型响应正文与音频/图片 base64。

## 二、关键指标

| 指标 | 来源 | 建议阈值 |
| --- | --- | --- |
| 执行请求量 / 状态码 | 反代 access log | 401/429 占比 > 5% 告警 |
| 执行耗时 P95 | `workflow execution completed` 前后时间差 | > 20s 告警（`maxDuration=30`） |
| 节点失败率 | `node execution failed` | 5 分钟 > 10% 告警 |
| 限流存储类型 | `/api/health.rateLimitStore` | 多实例环境必须为 `redis` |
| Redis 限流降级 | `Redis rate limit unavailable` | 出现即告警 |
| 进程存活 | `HEALTHCHECK` | 连续 3 次失败重启 |
| 内存/CPU | 容器指标 | 内存 > 80% 持续 5 分钟告警 |

## 三、排障路径

1. **确认存活**：`curl /api/health` → `status=ok`。
2. **确认鉴权**：无令牌 401、超限 429、payload 错误 400/413 均有稳定错误码。
3. **确认执行**：SSE 逐行输出 `node_start → node_complete → complete`；若一次性输出，检查反代缓冲。
4. **定位节点**：`node_error` 含 `nodeId` 与原因（`JavaScript execution error` / `SSRF protection` / `requires a prompt`）。
5. **定位模型**：AI 节点错误会保留 provider 错误消息；无 Key 时表现为鉴权失败，检查部署 Secret。

## 四、日志采集建议

- 容器 stdout → Loki / CloudWatch / 阿里云 SLS，按 `level`、`module` 建索引；
- 错误日志单独落一条告警通道，避免与访问日志混流；
- 保留 7–30 天，安全事件按合规要求延长；
- **不要**把日志写入镜像或仓库。

## 五、值班检查清单

- [ ] 每日：401/429 比例、节点失败 Top 3、P95 耗时
- [ ] 每周：Redis 限流降级次数、Provider 配额与费用
- [ ] 每月：日志脱敏抽检、告警阈值复核、回滚演练
